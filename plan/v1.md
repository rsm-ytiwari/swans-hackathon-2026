# V1: what we ship at 3:30 (PROPOSED, becomes D-011 on Yash's "yes")

## The promise (one line for the pitch)
Open any PI matter and know in 90 seconds what it is, what's blocking it, and what's wrong with it, with
every line one click from its source; then give each treating provider an attorney-approved view of
only what they need.

## Why this is valuable (who pays, for what)
- Attorney / case manager: replaces "read everything or ask a colleague" (slide 6). The value is the
  *judgment*: what's blocking, what contradicts itself. Lists are already in Clio.
- Provider: replaces "email the firm to ask if the case is alive" (slide 7) without leaking strategy.
- Swans engineers: read-only, runs on any matter, AI runs once per ingest and is cited and verified.

## V1 scope
**Firm view, first screen (budget: 5 blocks, ~180 words, no scrolling at 1440×900)**
1. Header: client, incident date, stage bar, last time anyone talked to the client (code)
2. Bottom line: 3 sentences, each clause cited (AI, cached, cites verified)
3. Do next: ≤5 rows, overdue first, "waiting on X" (code)
4. Worth vs coverage: estimated value, coverage, medical billed (with reconciliation check), liens (code)
5. Red flags: one-line titles, click → evidence (rule checks in code + AI contradiction finder)

**Firm view, second layer (on demand):** since you last looked (code filter + AI 1-line summary),
key events (AI picks ≤10 from the timeline, cited), providers & bills, full timeline.

**Provider side:** provider picker → live preview with dashed "hidden from provider" blocks → approve →
read-only link → view count. Plain-language labels. Deny-by-default firewall (built + tested).

**Engineering proof:** GET-only Clio client, guard test that fails on case-specific strings in `app/`,
second matter in Clio, cost per case from the usage log, AI-off mode where every code feature still works.

**Cut from V1 (V1.5 if time):** injuries extracted per provider from records (F6), drafted "case moved"
update (P4), sharing other providers' records (P6 UI), login (MOCK).

## How "nothing hardcoded" is guaranteed
- Code reads only `clio.db` (any matter id); firm-specific names live in `app/core/config.py`.
- Red flags: (a) generic rule checks (bills ≠ specials field, overdue, SOL near/past, no client contact in
  N days, treatment gaps, provider with bills but no records or reverse, coverage < specials); (b) AI
  contradiction finder over notes/emails/fields/document text; a flag is shown only if both quoted
  claims are found verbatim in their cited sources.
- Sapini's known contradictions are an eval set (recall), never code.
- Any provider: `LLM_PROVIDER=anthropic|gemini|ollama`, fallback chain; no provider → AI blocks say
  "AI off", everything else works.
